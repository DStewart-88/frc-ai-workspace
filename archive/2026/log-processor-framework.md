## Decisions (Doug, Nov 9)
- Build order: the app first (shell, folder watching, profile setup), then add analysis modules into it once the process works.
- **Anyone on the team should be able to run it at an event**; troubleshooting can fall to Doug or another tech-savvy adult. Normal use must be plug-in-logs-and-click simple.
- The team will likely keep last year's code format (BaseComp-style), not the AdvantageKit IO rewrite (that was educational for Doug). The code scanner targets the BaseComp layout.
- **Profiles live in the app instance** (made when a team first runs the app on a computer), not in the robot repo. Using Pitwall must not require a robot code change.
- **Platforms:** Doug develops and tests on his Ubuntu computer. The pit laptop will likely run Windows (the team can make sure Python is on it).
- **Modules:** Pitwall will show many data summaries from the logs; **power is one module**. The battery/brownout-charge estimate belongs inside the power summary, not a separate module (Doug, Nov 9).
- Doug tested the app and the Linux installer (Nov 9): works; made a robot profile with the setup page (same as the hand-made one). Small report/app tweaks parked.
- Learned: closing the browser tab doesn't stop Pitwall (by design: it keeps watching log folders); Quit in the page stops it.
- **Page structure (Doug, Nov 10):** event page = overview of each module's topline → a tab per module → match pages; switching module for the same match must be one click. Chose tabs inside one HTML file per page (option 2) over a file per tab.
- **Multi-team support parked (Nov 11):** focus on Team 88 first; other teams' public code/logs noted in `claude/pitwall-other-teams-testset.md` for later.
- **Project structure (Nov 13):** Pitwall stays in this 2026 project for now; Pitwall's 2027 development will happen in a 2027 robot project. A separate chat will distill this project for 2027. When that project is made, write Pitwall's status/decisions into a `docs/` folder in the frc-pitwall repo and sync the repo there (project docs, chats and project memory don't carry across projects).
- **Event dates (Nov 14):** FMS match days are enough; Doug declined a Blue Alliance lookup as not worth the complexity.
- **Practice (Nov 17):** open-ended practice/drilling stays out of Pitwall (better answered by targeted log analysis with AI). Only practice matches run as matches (DS practice mode, which the team uses) get Pitwall reports, organized by match, by day, and by the stretch between events; same counting rules as events (dead/short runs shouldn't weight averages).
- **Health tab (Nov 19):** device status first, then wear (tread), then CAN utilization and loop timing. No power faults in Health (Power covers them). Inspection due is a small, non-urgent line: a loud warning repeated every match would train people to ignore alerts. Older logs without the health monitor only need CAN/loop.

- **Charge before the first brownout (PR #13, 9d1c8f0, Nov 9):** in the power module. Per match: Ah used before the first brownout, Ah used after it, lowest-voltage margin over 6.75 V (ANALYSIS_VERSION 4). Event card after the battery chart: bar per match (before navy, after red; no-brownout faded with volts to spare), event median dashed line, summary; comparison row for the median; match brownout tile mentions both. Report version 5.
  - **Why no "charge left" estimate:** Doug asked whether logs can estimate total capacity / charge left. Batteries start charged (12.6–12.9 V rest) and first brown out after only 1.8–5.8 Ah of a ~18 Ah rating: the limit is holding voltage under 250 A peaks, not charge. A model (10 s windows fitting V = E − R·I, excluding brownout ticks; loaded voltage at 240 A starts ~8.8–9.2 V, falls ~0.25–0.3 V/Ah; R ~11–13 mΩ early → 14–18 late, includes wiring) was backtested: predicting each of the 20 fall brownout matches' first brownout from data up to 60%/80% of it ran late by a median 1.5/2.2 Ah, several by 10+ Ah (voltage collapses suddenly near the end). So Pitwall reports measured numbers only.
  - Fall medians: charge before first brownout NERD 4.12 Ah, River Rage 4.74, BOB 4.81 (pooled 20 matches: median 4.7, range 1.8–5.8); after it 1.87 / 1.14 / 0.44 Ah (pooled median 0.95, range 0.1–3.7). No-brownout matches used 4.6–6.1 Ah (River Rage Q12 6.12 Ah with none; NERD Q9 browned at 1.77 Ah with 113 s left) — points to battery differences. **Logging a battery ID per match** would allow per-battery tracking and a real per-battery "charge to brownout" estimate.
